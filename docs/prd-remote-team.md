## 1. 定位与用户

**Chiron 是一个可私有化部署的 AI Agent 工作台**，面向需要在真实代码库里长期使用 Agent 的
个人与团队：

- 开发者：让 Agent 读/改项目、跑命令、审阅改动，过程可见、可干预、可回滚；
- 团队管理员：统一模型/密钥/配额/审计，成员用浏览器访问，不必每人装客户端；
- 对数据边界敏感的组织：全部组件与数据可留在自有主机，密钥可接 KMS。

**不做**：通用聊天机器人、公有 SaaS 多租户平台、任意第三方代码的不可信执行市场。

## 2. 形态与边界

| 形态 | 说明 |
|---|---|
| **Windows 桌面（本版本唯一部署形态）** | Electron 壳拉起 Go 网关 + Python 引擎 + embedded PG/Redis；身份绑定 Windows 账户 |
| 团队 Web | 同一桌面程序作为服务端，Caddy/Nginx 终止 TLS；成员浏览器登录 |
| 远程模式 | 桌面只保留界面，`/v1` 请求发往自托管服务端 |

硬边界（如实承诺）：

- **单机部署没有副本冗余**：主机宕机 = 服务中断；保障手段是备份 + 恢复演练，不是 HA。
- **无内嵌终端**。**Git 写操作已按 N5 开放本地闭环**（stage/unstage、commit、discard(stash)、
  分支创建/切换，仅人触发、路径只取当前 status 条目、全过程审计）；**不提供 push**、force、
  `reset --hard`、rebase、merge、冲突解决与历史改写 —— 所以"开 PR"仍需用户在本机
  或 GitHub 手动推送。
- Linux 容器/WSL 编排**不在本版本承诺**；Kiri `container` 挡位代码已具备，真实环境验证待做。
- 发布签名尚未接入（自动更新只校验发布清单 SHA-512）。

## 3. 已交付能力

### 3.1 Agent 与协作

- 深度循环：多轮、工具批处理、预算/轮次/时长/费用五轴、取消与断流恢复、压缩与回读；
- steer：顶层会话运行中追加指令；子 Agent 按 run 追加（网关归属校验 + 引擎内网端点）；
- 子 Agent：模型自主委派、界面「＋委派」、nested run、并行、独立预算、事件回放与面包屑、
  停止/重试/看板（运行中/完成/失败）；
- 审批与提问：主/子 Agent 同一套票据，超时与归属校验；后台任务可跑在独立队列；
- **验证闭环（N6/N6.1）**：从本轮**真实执行过**的 `shell_exec` 给出通过 / 失败 / 未验证，
  失败或未验证时自动补一轮修复；项目可在 `.chiron/verify.json` 的 `commands` 里声明
  验证命令（未配置时按 test/typecheck/lint/build 关键字识别）。

### 3.2 工作台

- 浏览与审阅：只读文件树与预览、改动列表与单文件 diff、Git 提交历史/提交 diff、
  项目内容搜索、本回合改动审阅、还原点时间线与回滚；
- **审阅→修复往返（N2）**：diff 行级/多文件意见一键发给 Agent，修复回合结束（含失败/取消）
  后自动重拉 diff；
- **Git 写入闭环（N5）**：勾选暂存、只提交已暂存内容、丢弃未暂存改动（先 stash 可恢复）、
  分支列表/创建/切换；写操作受项目锁与活跃 run 约束，仅服务端项目 + owner/绑定者；
- **多项目并行（N7 v1）**：项目标签切换，各项目恢复自己的活跃会话与工作台开合状态；
- 验证徽标（N6）：diff 头部显示本轮验证结论（通过/失败/未验证）。

### 3.3 知识与记忆

- 知识库：PageIndex 自托管/Cloud，批量与文件夹导入、同批/跨批内容去重、引用带页码深链；
- 记忆：条目管理、冲突待裁决、整理与摘要、会话内「保存为记忆」。

### 3.4 扩展与团队

- 技能、Agent Profile、MCP 插件、资源市场；安装前展示 env/model/approval/fs/net/shell 权限；
- 账号/邀请/角色、会话分享、会话地图、后台（用户/模型/服务商/配额/审计/运行时监控）。

### 3.5 安全与合规

- 执行隔离开关与 fail-closed（不可用即拒绝执行）；
- 分享链接的密码失败按 (分享, 来源 IP) 计数，超阈值短锁 60 秒（Redis 不可用时 fail-open）；
- Provider 密钥信封加密（v2）+ 可插拔 KMS + 轮换；Redis 镜像也只存密文；
- `no_retention` 隐私模式（后台任务在该模式下明确拒绝，而非"写一半再声称不留存"）；
- 审计日志、敏感操作审批、租户/用户日费用熔断。

## 4. 非功能基线

- **认证**：JWT + 撤销纪元/黑名单；存储不可用返回 503（不把故障伪装成登出）；
- **长连接**：SSE 逐帧写期限、指数退避重连、心跳看门狗、断线补拉与跨实例重放；
- **队列**：消费组 + 幂等键 + 围栏；停机拒绝新 spawn、排空在途；DLQ 重投不裁剪 PEL；
- **并发与超时**：引擎实例的直连提交与自动续跑共享 run 上限（超限 429，自动续跑跳过本轮）；
  DB 操作在调用方没有 deadline 时 30s 兜底，池耗尽不会无限挂起；
- **启动门禁**：schema 不匹配拒绝启动（只开诊断端口）；迁移由发布流程执行；
- **可观测**：`/metrics`（网关/引擎）、`/health` 与 `/ready`、最小告警集
  （`deploy/prometheus-alerts.yml`）。

## 7. 已定决策

- **部署**：本版本仅 Windows 桌面端；容器/WSL 编排不进承诺。
- **密钥**：进程内信封加密 + 可插拔 KMS，不引云 SDK；Redis 镜像只存密文。
- **隔离**：档位收敛为无隔离 / 作业对象 / 低完整性 / 容器（Kiri）；`restricted`、
  `appcontainer` 已移除，旧配置值映射到低完整性。Kiri 按需下载、不内置、SHA-256 校验；
  不可用即拒跑；规格不可放宽。
- **插件化**：不做 Cordis 式"一切皆可替换"；只做能力 seam + 声明式 bundle。
- **MCP 注册表**：不合并统一注册表；**不做**定时触发原语。
- **共享会话**：分享页只读；导入/分支（F11）需单独设计，不默认放开。
- **演进取舍（2026-11-27，2026-11-28 复核）**：不做 N9 跨项目知识库、N11 市场签名治理、
  N12 项目级策略中心；N6/N7 已交付，优先级按 §5.4 转向 N14；N1（检索评测）与
  N4（项目级 RBAC）于 2026-11-28 决定暂不做。
  其中 N11 的签名根与 H51 同源，H51 决策变化时应重新评估市场签名。
- **Git 写入（N5，2026-11-28 合入）**：只做**人触发**的本地写操作；写命令禁用
  仓库 hook/filter/签名（`core.hooksPath` 空目录、filter 覆写 `cat`、`commit.gpgsign=false`），
  路径只接受当前 status 条目；不做 push/force/历史改写；当前仅服务端项目与
  owner/项目绑定者，client 项目与团队普通成员不开放。N8 若要排期，需先在此处写明
  push 的最小可接受口径（仅当前分支、无 force）。
